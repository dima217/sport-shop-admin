# Техническое задание: Sport Admin

## Исходные данные

Интернет-магазин спортивных товаров: каталог товаров по категориям, складские остатки, заказы покупателей, пользователи и тикеты службы поддержки.

---

## Техническое задание

Разработать веб-приложение **«Sport Admin»**, центральной функцией которого является администрирование интернет-магазина спортивных товаров: управление каталогом, складом и заказами. Требуется реализовать **аутентификацию** для входа администраторов и кладовщиков с защитой маршрутов и автоматическим выходом при истечении токена.

Необходимо обеспечить **управление категориями** товаров: просмотр списка категорий, создание, редактирование и удаление категорий с учётом иерархии (родительская/дочерняя категория). Требуется **управление товарами**: просмотр списка с фильтрацией и поиском по названию, категории, бренду, размеру, цвету и наличию; создание, редактирование и удаление товаров; установка и снятие скидок на товары. Обязательно предусмотреть **управление заказами**: просмотр списка заказов с фильтрацией по статусу (ожидание, в обработке, отправлен, доставлен, отменён), детальная информация по заказу (состав, доставка, оплата) и изменение статуса заказа.

Ключевой элемент — **статистика (Dashboard)**: общая сводка по заказам (количество по статусам), по товарам (в наличии, нет в наличии, низкий остаток), по выручке (за день, неделю, месяц, всего), а также графики выручки, распределение заказов по статусам, топ продаж и товары с низкими остатками. Требуется раздел **пользователи**: просмотр списка пользователей с возможностью назначения роли (пользователь/администратор), блокировки и разблокировки учётной записи. Необходим раздел **поддержка**: список обращений (тикетов) с фильтрацией по статусу (открыт, в работе, решён, закрыт), просмотр тикета с ответом администратора и смена статуса.

Приложение должно работать с **внешним REST API** (база данных и бизнес-логика на сервере) для хранения каталога категорий, товаров, заказов, пользователей и тикетов. Обеспечить **поиск и фильтрацию** по разделам: товары — по названию, категории, цене, бренду, размеру, цвету, наличию и сортировке; заказы — по статусу; тикеты — по статусу. В итоге приложение формирует **сводную статистику** магазина на основе данных API: заказы, выручка, остатки и продажи товаров для принятия решений администратором и кладовщиком.

## Краткая структура (для справки)

| Раздел            | Назначение                                                                 |
|-------------------|----------------------------------------------------------------------------|
| Аутентификация    | Вход по логину/паролю, JWT, защита роутов, logout при 401                 |
| Категории         | CRUD, иерархия (parentId), slug, изображение                               |
| Товары            | CRUD, фильтры, скидки, остатки, размеры, цвета, бренд, изображения        |
| Заказы            | Список, детали заказа, смена статуса, состав, доставка, оплата            |
| Статистика        | Сводка заказов/выручки/остатков, графики (Recharts), топ продаж           |
| Пользователи      | Список, роль, бан/разбан                                                   |
| Поддержка         | Список тикетов, детали, ответ администратора, статус                       |
| API               | Единый базовый URL, Bearer-токен, обработка 401                           |
